# 十一校园助手 · BNDS Campus Companion

> 帮助 BNDSer（十一学校学生）在校内学习与生活时，把散落在多个平台的信息整合到一个入口，并借助 AI 提供人生规划与个性化指导。

**一句话定位**：面向十一学校学生的个人化校园信息中枢 —— 数据汇聚、日程驱动、AI 陪伴。

---

## 一、项目背景与痛点

十一学校学生在校内学习生活中，接触到的信息分散且割裂：

- 课表、通知、过程性评价分散在**学校云平台**、**ManageBac** 等多个系统；
- 课程、作业、评价、成绩、社团活动信息互相孤立，缺少一个统一视图；
- 缺少系统化的规划工具，长期目标与每天的日程脱节；
- 评价与成绩散落各处，难以累积成"个人成长账本"；
- 缺少一个**理解"我"**的助手来解读这些数据、辅助决策。

我们想做的，就是把以上分散信息收敛到一个**统一的、日程驱动、AI 加持**的个人化平台。

---

## 二、目标用户与核心价值

- **目标用户**：十一学校在校学生（BNDSer）
- **核心价值三角**：

| 价值 | 说明 |
|------|------|
| 🧭 人生规划 | 把长期目标与日常执行打通，让规划落地 |
| 🗂️ 校内信息整合 | 让分散的多平台信息有一个统一入口 |
| 🎓 个性化学业指导 | 基于个人数据 + AI，给出针对性建议与交流渠道 |

---

## 三、产品设计原则（最重要 · 先读这个）

> **AI 是参谋，不是决策者。** 平台上每一份建议、每一条路径、每一个目标，最终**由用户自己拍板**。

| 原则 | 含义 |
|------|------|
| 🫵 **决策权永远在人** | AI 只提供分析、选项、利弊与提醒，永远把选择权交还给用户 |
| 🙅 **建议不越位（不喧宾夺主）** | 个性化辅导必须围绕用户的路径，**围绕人，而非牵着人走** |
| ✅ **可拒绝** | 用户可对任何建议说"不"，平台尊重并记录用户的选择 |
| ⏳ **待定是常态** | 人生充满未知，路径上任何节点都允许"待定"，AI 不强求、不催促 |
| 🔄 **可推翻** | 用户随时可调整、暂停、重写自己的路径与目标 |
| 🔍 **透明可溯源** | 每次建议都说明"为什么这么建议"，方便用户判断与质疑 |

---

## 四、新用户接入（Onboarding）

首次进入平台时，不是一个冷冰冰的表单，而是一次**与 AI 的初次对话式共创**：

1. **了解"我"**：选择一个或多个**兴趣板块**（学科、社团、艺术、体育、科创、升学方向……），说一说**对人生的想法**（哪怕很模糊）。
2. **AI 不评判、只倾听**：AI 把这些想法整理成初步认知，不急着下结论。
3. **共创人生路径**：AI 提出一个**可修改的路径草案**，用户增删、排序、补充分支。
   - 用户"没有太多想法"时，**任何位置都可以标记为"待定"**，AI 不强求补全。
4. **共创目标**：在路径上共同商定**长期目标**与**短期目标**，同样允许"待定"。
5. 这些内容沉淀为用户的**个人路径档案**，成为后续一切 AI 辅导的依据。

> 关键：接入阶段是**协作**，不是"填表提交"。用户永远是发起者，AI 永远只做启发与整理。

## 五、核心功能模块

### 5.1 人生规划（以"人生路径"为核心）

- **人生路径**是平台的核心对象：由兴趣板块 + 人生想法 + 长期目标 + 短期目标构成的一条**可折叠、可变化**的路径。
- 路径上的每个节点都有**状态**：`进行中 / 已达成 / 待定 / 已放弃`。
- 支持把短期目标拆解为阶段性任务，并落到日程。
- 形成长期个人成长档案，可回顾、可复盘、可追踪。
- **任何节点随时可"待定"或推翻**，AI 只协助梳理，绝不越权决定。

### 5.2 校内信息整合
- 统一接入多平台数据（见第六节）
- 形成统一 **Dashboard** 视图
- 支持自动/定时更新，保持数据新鲜

### 5.3 个性化学业指导（大模型）
- 平台内接入大模型
- **上下文核心是"人生路径"**：分析、建议、策略都围绕这条路径展开
- 数据输入：个人规划（路径）、过程性评价、考试成绩、近期日程
- 输出：个性化分析、学习建议、策略与提醒
- 提供**交流渠道**（AI 对话 / 消息提醒）

> ⚠️ **红线**：个性化辅导必须**服务于用户自己的人生路径**，只提供"选择与利弊"，**绝不替用户做决定**。当用户的目标与 AI 的"最优解"冲突时，**一切以用户为准**。

## 六、数据整合方案（信息源）

| 信息源 | 数据内容 | 接入方式 |
|--------|----------|----------|
| 十一学校云平台 | 课表、过程性评价、考试成绩、校内通知 | 待确认：API / 导出导入 / 手动 |
| ManageBac | 课表、作业、评分、IB 相关资料 | 待确认：同上 |

## 七、功能实现细节

### 7.1 课表同步到日程
- 解析多来源课表，去重合并为一份统一课表
- 生成日历（ICS / 订阅链接），可同步到手机/电脑系统日历
- 数据变更时自动更新，冲突检测与去重

### 7.2 专注模式（基于课表）
- 读取当日课表与自习时间
- 在"学习时段"自动或手动开启专注模式
- 屏蔽干扰（通知降噪、应用白名单）
- 可选增强：白噪音、番茄钟、专注时长打卡记录

### 7.3 平台内大模型接入
- 聚合个人数据 → 构建结构化上下文（以人生路径为主轴）
- 生成个性化分析、建议、学习策略
- **重要**：数据脱敏后再进入大模型，严格保护隐私
- **始终以"辅助决策"为边界**，提供选项而非替用户拍板

## 八、技术架构（初版草案）

```
┌─────────────────────────────────────────────────┐
│  客户端（Web / 小程序 / 移动端）                      │
│   Dashboard · 日程 · 专注模式 · AI 对话              │
└───────────────────────┬─────────────────────────┘
                        │ HTTP / 实时
┌───────────────────────▼─────────────────────────┐
│  后端统一服务                                     │
│  数据接入 · 解析归一化 · 日程 · 权限 · AI 编排        │
└──────────────┬──────────────────┬───────────────┘
               │                  │
   ┌───────────▼───────────┐  ┌──▼──────────────────┐
   │  数据层               │  │  AI 层               │
   │  用户数据·人生路径·课表 │  │  LLM · Prompt 编排   │
   │  评价·成绩·本地/云端存储  │  │  RAG（基于个人数据）   │
   └───────────────────────┘  └─────────────────────┘
```

- **协议/同步**：日历(ICS/CalDAV)、通知推送
- **数据流**：用户授权 → 数据接入 → 归一化 → 统一存储 → 展示 / 日程 / 专注 / AI
- **核心对象**：`人生路径`（含兴趣板块、长期/短期目标、节点状态）

## 十、隐私与合规（必读）

- 涉及**成绩、过程性评价等敏感个人数据**，须最小化收集、明确用途
- 数据用户可查询、可导出、可删除
- 进入大模型前必须先**脱敏 / 匿名化**
- 遵循教育数据相关法律法规与学校规范
- **未经授权的数据抓取必须规避**，优先采用授权 / 官方导出
- `人生路径` 属于高度个人化内容，默认仅用户本人可见
